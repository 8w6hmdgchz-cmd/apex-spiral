## 3. APEX-MEM 重点拆解

### 3.1 定位

> "**The strongest multi-dimensional memory system for AI agents.** A drop-in replacement and **superset** of OpenClaw's memory subsystem, implemented in pure Rust."

**直白说**：这是冲着**取代 OpenClaw 记忆子系统**来的。

### 3.2 5 维记忆模型（核心创新）

| 维度 | 含义 |
|---|---|
| **Working** | 短时记忆（当前会话） |
| **Episodic** | 情景记忆（"我那天做了什么"） |
| **Semantic** | 语义记忆（"X 是什么"） |
| **Procedural** | 程序记忆（"怎么做 Y"） |
| **Declarative** | 陈述性记忆（事实） |

对比 OpenClaw 默认的 3 维（Session/Working, Long-term, Wiki）—— 多了 2 维。

### 3.3 三大新增能力

| 能力 | 说明 |
|---|---|
| **自愈（APEX diagnosis）** | ΔG 自由能诊断，自动修复损坏/碎片记忆 |
| **自进化（Evolution engine）** | 遗传算法调优检索权重 |
| **梦境整合（Dreaming）** | 后台定期 dedup、merge、promote、发现新关系 |

### 3.4 协议兼容矩阵

兼容 **4 个**主流生态：

| 上游 | 兼容层模块 |
|---|---|
| OpenClaw | `src/compat/openclaw/`（直接打自己目标） |
| mem0 | `src/compat/mem0/`（含 migration 工具） |
| letta | `src/compat/letta/` |
| langmem | `src/compat/langmem/` |

### 3.5 技术栈（63 个依赖）

**性能核心**：
- `tokio` 全功能运行时
- `parking_lot` + `dashmap` + `arc-swap` + `once_cell` —— 高性能并发
- `blake3` + `sha2` —— 哈希

**存储层**：
- `rusqlite` 0.31（SQLite FTS5 全文索引）
- `tantivy` —— BM25 搜索引擎
- `petgraph` —— 图存储

**接口层**：

- REST API + CLI 双入口
- 10 个 MCP tools

## 4. ⚠️ 关键风险（必须警惕）

### 4.1 名字撞车

**用户自己的项目叫"APEX"**（APEX_TOKEN_OPTIMIZATION_MD.md、apex-spiral、APEX 框架）。
**APEX-MEM 也在用"APEX"**这个品牌名，并且其"ΔG 自由能诊断"概念**和用户自己的 APEX 框架**几乎同源。

**风险**：
- 名字混淆（用户跟项目沟通时容易说错）
- 知识产权风险（如果用户后续要商业化 APEX，可能有冲突）
- 社区认知冲突（用户 vs APEX-AGI 的 APEX）

### 4.2 直接打 OpenClaw 的脸

- 标题：~~"OpenClaw 兼容"~~ → **"OpenClaw 替代品"**
- 描述里把 OpenClaw 现有的能力列为"被超越对象"
- 甚至**自己建了 `apex-agi/apex-mem` 仓库地址**（不是 hernandez42），要做独立品牌

**含义**：这不是友好的"上游贡献"，是**正式宣战**。

### 4.3 没有社区验证

- APEX-MEM 只 1 个 commit（v0.2.0 首发）
- 没有 issue 反馈
- 没有 PR 历史
- 集成测试只有 2 个

**判断**：质量可能 OK，但**生产环境慎用**。

### 4.4 hermes-agent 分支异常

- 16 个分支全是 `fix/security-*-xxx` 形式
- 看起来**专攻安全补丁**，可能是 NousResearch 上游的安全分支同步
- 也有可能是自己改完没合并的临时分支

**建议**：先不要直接用 main，看 commit history 再决定。
